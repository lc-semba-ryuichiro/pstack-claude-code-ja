# Model the Domain

条件分岐に散らばらせるのではなく、データ構造にドメインをエンコードすること。適切な構造は不正な状態を表現不可能にし、分岐を消し去ります。

散らばったブーリアンやフェーズのチェックの代わりにステートマシンを、緩いパラメータの代わりに型付けされたモデルを、複数ファイルにまたがる分岐の代わりにマップ、レジストリ、または判別共用体（discriminated union）を、アドホックな変更の代わりにリデューサーを、そしてアクセスパターンが要求する場所にはインデックス、キュー、または正規化されたコレクションを活用します。

無理に適用しないこと。形状が明確で局所的、かつ拡大しそうにない場合は退屈なコードを保ち、分岐や不正な状態を排除せずに間接性（indirection）だけを追加する抽象化を疑います。

これを怠ったサイン: `if/else` チェーンをさらに1つ増やす機能、または最初のブーリアンと同期し続けなければならない2つ目のブーリアンの存在。
