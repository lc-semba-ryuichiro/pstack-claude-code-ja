# Explain the Number

- **実行する前に決定事項を書き出す:** 決定を変えうる結果と、ノイズフロア（noise floor）を明記します。実行ごとのばらつき（spread）が効果よりも大きい場合は中断します。
- **「なぜ2倍にならないのか？」と問う:** 実行中のプロファイルやカウンターから、結果をバウンド（制限）しているリソースやコードパスを特定します。コードを読んでの推測はリミッターにはなりません。
- **その数値が他に何を測定している可能性があるかをリストアップする:** （エラー、スキップまたはキャッシュされた作業、実行されなかったコード、チューニングされていない側、ノイズ、小さすぎて影響しない部分など）、それぞれを証拠をもって排除します。
- **数値とともに、実行回数、ばらつき、リミッターを記録する。**

パフォーマンスの数値については、[benchmark-checklist](../benchmark-checklist/SKILL.md) スキルを実行してください。評価結果については、すべての実行がタスクを完了したか、試行やモデル間でギャップが維持されているか、そのシナリオが重要かどうかを問いかけます。
