# Swarm

## 開始する

何かを起動する前に、フェーズごとに1つのエントリを持つ Todo リストを作ります。`TodoWrite` があればそれを使い、なければ返信内にリストを保持して各フェーズで更新します。

1. Frame（枠組み設定）
2. Fan out（並列展開）
3. Aggregate（集約）
4. Report（報告）

## フェーズ A：Frame（課題設定）

1. 完了述語（done predicate）と、swarm が返すべきアーティファクトまたはレポートを明記します。
2. 実行形態を選択します。スライスに分割するか、同一の指示書（brief）で N 個のワーカーを競わせる（レース）か、あるいはその両方を組み合わせます。レースまたは混合形態の場合は、スポーンする前に `first pass`、`rank all`、または `best-of` を宣言します。
3. `~/.claude/rules/pstack-models.md` の `swarm workers` 行からワーカーモデルを選択します。ルールまたは該当行がない場合は、`opus high` を使用します。値は `<model> <effort>` の形なので、`Agent` 呼び出しに `model: "opus"`、`effort: "high"` のように渡します。`auto` または `inherit-parent` の場合は、ワーカーが親モデルで実行されるよう `model` を省略します。`Agent` ツールが値を拒否した場合はデフォルトを使用し、その旨を伝えます。デフォルトも拒否された場合は、エラーメッセージを見て同じ `model` で最も近い有効な effort を使用します。モデルレースの場合は、各アームのモデルを事前に明記します。ジョブに応じた各サブエージェントの推論レベルは、[**poteto-mode** スキル](../poteto-mode/SKILL.md)の Subagents セクションに従って選択します。
4. 書き込みを行うワーカーには、それぞれ専用の書き込み先出力を与えます。ワーカーがコミットを検証または測定する場合、各指示書には正確な SHA を明記します。測定用の指示書には測定方法（サンプル数、1サンプルの定義、順序）も明記します。ワーカーは結果にその両方を記録します。

## フェーズ B：Fan out（並列展開）

ステップ3のモデル（`auto` や `inherit-parent` の場合は `model` を省略）を指定し、`subagent_type: "general-purpose"`、`isolation: "worktree"` で、1つのメッセージ内で N 個すべてのワーカーを同時に起動します。各ワーカーは自分専用の Git worktree で作業します。

各指示書には、ワーカーが最初にチェックアウトするブランチまたはコミットを書きます。親がチェックアウト中のブランチは別の worktree ではチェックアウトできないため、現在のブランチを基点にする場合はその SHA を書き、そこから新しいブランチを作らせます。未コミットの変更は worktree に入りません。ワーカーに必要な場合は、基点の SHA に対する `git diff HEAD` の出力をパッチファイルに書き出し、そのパスと未追跡ファイルのパスを指示書に列挙して、適用・コピーさせます。書き込みを行うワーカーには、成果を自分の worktree でコミットし、ブランチ名と SHA を報告するよう指示します。

すべての指示書は単体で完結させます。目標、スコープ、正確なスライスまたはレースアーム、検証方法、および報告内容を含めます。レポートには証拠を添えて `PASS`、`ISSUES`、または `BLOCKED` を使用します。欠陥を証明できるワーカーは `ISSUES` を報告し、最初の1つだけでなく証明できるすべての問題を列挙します。

ワーカーが脱落（ドロップアウト）した場合は、N-1 で続行し、その旨を記録します。

## フェーズ C：Aggregate（集約）

終了した結果（terminal results）を読み取ります。指示書で指定された SHA と測定方法が記録されていない結果は破棄し、そのワーカーを1回だけ再スポーンします。2回目も漏れていた場合はギャップとして記録します。ギャップはパス（合格）としてカウントしません。カバレッジ調査では、必要なすべてのスライスに結果が必要です。レースでは、事前に宣言した選択ルール（`first pass`、`rank all`、または `best-of`）を適用します。ワーカーの生ダンプをそのまま貼り付けないこと。

## フェーズ D：Report（報告）

結果テーブル、問題の1行サマリー、ギャップやドロップアウト、および使用した場合はレースルールを含む、1つの統合されたチャット内レポートを返します。
