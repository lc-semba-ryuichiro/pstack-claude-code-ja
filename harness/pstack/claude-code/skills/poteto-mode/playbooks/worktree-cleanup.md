### Worktree and simulator cleanup

1. **スナップショットと監査。** `df -h /` を記録し、`scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` を実行します（`principle-build-the-lever`）。`-b` を指定しない場合は `origin/HEAD` に対して `MERGED` をチェックするため、PR が別のブランチをターゲットにしている場合は `-b origin/<branch>` を渡します。手入力の `myrepo-worktrees/x` では `.claude/worktrees/x` にあるワークツリーを見落とすため、パスは手入力せず `git worktree list` から読み取ります（`principle-encode-lessons-in-structure`）。各ワークツリーをサイズ、経過時間、マージ状態、未コミット作業、PR 状態、および最後に触れた最新チャットで分類し、バケットを提案します。トランスクリプトのスキャンは遅いため、バックグラウンドで実行します。
2. **バケットは助言であり、削除許可ではない。** ピン留めされたチャットとアクティブなチャットこそが本物の成果物です（`principle-prove-it-works`）。ユーザーまたはサイドバーからその一覧を取得し、すべての候補と照合します。ツール（lever）がユーザーがピン留めしたワークツリーを `safe` とマークすることがあるため、ピン留め一覧を優先します。
3. **削除前に使用状況を検証する。** すべての `verify-recent-chat` 行や疑わしいものについては、サブエージェントをファンアウト（fan-out）してトランスクリプトを読ませ、そのチャットがピン留め中または進行中であるか、またどのワークツリーに触れているかを報告させます（`principle-guard-the-context-window`、トランスクリプトはデータ量が大きいため）。ピン留めされたチャットはバックグラウンドのサブエージェント経由で兄弟ワークツリーに arena や再現（repro）ツリーを生成することがあり、それらはサイドバーに名前が一度も出なくても使用中です。ジョブに応じた各サブエージェントの推論レベルは、Subagents セクションに従って選択します。
4. **不可逆な損失の前で一時停止する。** `wip:N` は追跡中の未コミット編集が N 件あることを示します。クリーンなワークツリーの削除はブランチから復元可能ですが、未コミットの作業は失われるため、まず diff を示して判断を仰ぎます。`scratch:N` は未追跡の使い捨てファイルなので削除して問題ありませんが、ファイル名を明記します。自律性（Autonomy）のルールに従い、クリーンでマージ済みかつ未使用のものはそのまま進め、`wip` と使用中のものは一時停止します。
5. **確定したセットを削除（prune）する。** パスごとに `git worktree remove --force <path>` を実行します。無視されたビルド成果物が残ってディレクトリが消えない場合は `rm -rf` で削除し、その後 `git worktree prune` を実行します。ブランチ参照は残るため、コミットが失われることはありません。`df -h /` と再一覧表示で確認します。
6. **シミュレーターとその他の容量回収手段。** 通常、次に大きな容量削減になるのはシミュレーターです。`xcrun simctl --set testing delete all`（XCTestDevices クローン）、`xcrun simctl delete unavailable`、および古いランタイムに対する `xcrun simctl runtime list` からの `runtime delete <id>` を実行します。さらに必要な場合は、Xcode の `DerivedData` と `iOS DeviceSupport`、パッケージキャッシュ（pnpm、uv、brew、yarn）を対象にします。ユーザーが保持すると言っていないキャッシュのみを削除してください。

これはコードレビューでミスを捕捉できないままユーザー状態を削除する唯一のプレイブックであるため、上記のゲートそのものがレビューとなります。

**返信形式：** 回収された空き容量を含む実行前後の `df -h /`、削除したワークツリー、および残した各ワークツリーの1行理由（どのチャットが使用中か、または未コミット作業があるか）。
